# Source audit, October 2026

This audit covered the Python package (`src/netcast3r`, 60 files, about 25k
lines), the Svelte frontend (`web/src`), and the helper scripts (`tools/`).
It combined an automated rule pass with a manual review of the trust
boundaries: the HTTP router, the MCP tool registry, scope resolution, the
approval gate, the SQLite index, and the threaded runtimes.

The automated half is now a shipped capability, `codeaudit_scan`, so the
result can be reproduced:

```
.venv/bin/python -c "import sys; sys.path.insert(0,'src'); \
  from netcast3r import codeaudit; import json; \
  print(json.dumps(codeaudit.scan('src/netcast3r'), indent=2))"
```

The 31 remaining `src` entries are `info`: a typed handler such as

## Fixed

### High

1. **Approval binding was optional.** `_consume_approval` skipped the tool and
   argument-hash checks when the approval payload did not carry them, and
   `approval_request` only wrote them when it was given a tool name. A vague,
   unbound approval therefore opened every high-risk tool. Both checks are now
   mandatory, and `approval_request` refuses a request that does not name the
   exact tool and arguments. Regression test:
   `test_unbound_approval_cannot_open_a_high_risk_tool`.
2. **A caller could widen a mission's scope.** `_require_scope` unioned the
   caller's `scope` list with the mission's scope. An agent confined to
   `example.com` could pass `scope:["evil.example"]` alongside its mission id.
   When a mission is named, it is now the whole authorisation. Test:
   `test_caller_scope_cannot_widen_a_mission`.
3. **Scheme-less targets could bypass scope rules.** `scope._split` returned
   the raw host part for a target without a scheme, so `example.com@evil.example`
   was checked as `example.com@evil.example` while the request was dialled to
   `evil.example`. Both the scope splitter and the tool host parser now use the
   same `urlsplit` normalisation, which strips userinfo and ports. Tests:
   `test_scheme_less_userinfo_resolves_to_the_dialled_host`,
   `test_ports_do_not_hide_the_host`.
4. **Local analyzers were an arbitrary-file-read primitive.** `rea_analyze`,
   `reveng_analyze`, `auth_profile_import`, and `codeaudit_scan` accepted any
   path. `_guard_local_path` now resolves symlinks and refuses NetCast3r's own
   state directory (except artifact/download/results subtrees) and known
   credential stores (`.ssh`, `.aws`, `.gnupg`, `.netcast3r`, private keys,
   `.netrc`, `.env`). Tests: `LocalPathGuardTests`.

### Medium

5. **Burp/MCP scope check was key-based.** It only inspected a fixed set of
   key names and only recursed into dict items inside lists, so a URL in a
   plain string list or an unlisted key reached the operator's Burp unchecked.
   Every string is now scanned for absolute URLs and `Host:` headers.
6. **Browser tools returned data from out-of-scope pages.** `snapshot`,
   `click`, `type`, `press`, `wait`, `screenshot`, and `eval` did not re-check
   scope after navigation. They now re-check the resulting URL whenever a
   mission or explicit scope is supplied.
7. **`JobManager.recover` read the shared SQLite connection without the index
   lock.** It now calls `Index.running_run_ids()`, which takes the lock.
8. **`JobManager._handles` grew without bound.** A finished run now removes its
   handle. Test: `test_finished_jobs_are_not_retained`.
9. **A healthy provider could be retired by one transient error.** The strike
   counter was never reset on success. `_settle` now clears the strikes for the
   provider and model that just answered.

### Low

10. **The shipped Juice Shop recipe could never run.** Its base is
    `127.0.0.1:3000` but the runner always used the Academy-only scope. A
    recipe that names its own base now adds that host to the scope it declares.
11. **`HEAD` never matched a `GET` route.** The router now treats `HEAD` as
    `GET` (the dispatcher already drops the body). Test:
    `test_head_uses_the_get_route`.
12. **`subprocess` calls in `browser.py` and `tools/build_web.py` had no
    timeout.** Both now pass one.
13. **`Home.svelte` buffered paused events without a cap.** It now keeps the
    most recent 1800, like the main event list.

### Recorded as reviewed, not changed

- **Session cookie has no `Secure` flag.** The server binds the loopback only
  and `ALLOWED_HOSTS` is loopback, so the token is not reachable over a
  routable interface. Adding `Secure` would need a TLS termination story first.
- **`missions_create` / `missions_update` are medium risk.** An agent can
  declare a new scope or change one. This is the documented model: a scope
  list is an authorisation. The operator can see it and the action is audited.
  If agents should not self-authorise, the fix is a policy change (raise both
  to `high`), not a silent behaviour change.

## Notes on the automated pass

Eight dynamic-SQL sites (`store.py`, `server/index.py`) were flagged by the
`py-sql-fstring` rule. Each interpolates an identifier from a hardcoded
allow-list (column names, a fixed table tuple) and binds values with `?`. They
carry an inline `codeaudit: ignore py-sql-fstring` comment explaining why, so
the exception is visible in the report instead of hidden.

## Limitations

- The rule pass is pattern-based. It cannot see a logic flaw, a missing
  authorization check, or a race that only appears under load.
- The manual review was bounded to the trust boundaries above. It is not a
  formal proof.
- No findings from this audit were treated as vulnerabilities in a target;
  these are defects in NetCast3r itself.
